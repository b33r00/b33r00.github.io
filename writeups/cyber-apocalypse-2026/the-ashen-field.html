Three lines. Line 1 is a massive tuple of multivariate polynomials in variables x1 through x137. Line 2 is 137 bits (encrypted key). Line 3 is a hex string (encrypted flag).

The polynomial format and variable count pointed immediately to HFE — Hidden Field Equations, a multivariate public key scheme.

analysis

Quick script to inspect the polynomial structure:

import re

with open('output.txt') as f:
    lines = f.read().split('\n')

body = lines[0].strip()[1:-1]
polys = body.split(', ')
print("number of polynomials:", len(polys))
# 137

var_re = re.compile(r'x(\d+)\^(\d+)')
exponents = set()
for p in polys:
    for m in var_re.finditer(p):
        exponents.add(int(m.group(2)))

print("exponents found:", exponents)
# {2, 4}

print("cross terms:", any('*' in p for p in polys))
# False

Only exponents 2 and 4, no cross terms. This is the key observation.

In a standard HFE scheme the central polynomial is F(X) = X^(q^a) + X^(q^b) over an extension field. With q = 2, those exponents become 2^1 = 2 and 2^2 = 4. In characteristic 2, raising to a power of 2 is a Frobenius endomorphism — it is GF(2)-linear:

(a + b)^2 = a^2 + b^2   over GF(2)
(a + b)^4 = a^4 + b^4   over GF(2)

And since inputs are actual bits, x^2 = x and x^4 = x for all x in {0, 1}. So every output bit is just an XOR of some subset of input bits plus a constant. The whole system collapses to an affine map over GF(2):

ciphertext = M * plaintext + b   (mod 2)

Inverting an affine map over GF(2) is Gaussian elimination.

Root cause: HFE instantiated with base field q = 2. The Frobenius powers are GF(2)-linear, so on binary inputs the nonlinearity vanishes completely.

exploitation

Step 1 — parse the public key into a matrix. The coefficient of variable xi in polynomial j is the XOR-parity of how many times xi^2 and xi^4 appear (both reduce to xi on bit inputs).

N = 137
var_re = re.compile(r'^x(\d+)\^(\d+)$')
M, bvec = [], []

for p in polys:
    terms = p.split(' + ')
    coeff = [0] * N
    const = 0
    for t in terms:
        t = t.strip()
        if t == '1':
            const ^= 1
        else:
            m = var_re.match(t)
            if m:
                idx = int(m.group(1))
                coeff[idx - 1] ^= 1
    M.append(coeff)
    bvec.append(const)

print("matrix shape:", len(M), "x", len(M[0]))
# 137 x 137

Step 2 — Gaussian elimination over GF(2) using integer bitmasks for speed. The encrypted key c satisfies c = M * key + b (mod 2), so solve M * v = c XOR b.

encrypted_key = eval(lines[1].strip())
rhs = [encrypted_key[i] ^ bvec[i] for i in range(N)]

rows = []
for i in range(N):
    mask = 0
    for j in range(N):
        if M[i][j]:
            mask |= (1 << j)
    rows.append((mask, rhs[i]))

work = rows[:]
pivot_cols = {}
r = 0

for col in range(N):
    piv = next((i for i in range(r, N) if (work[i][0] >> col) & 1), None)
    if piv is None:
        continue
    work[r], work[piv] = work[piv], work[r]
    pivot_cols[col] = r
    pm, pa = work[r]
    for i in range(N):
        if i != r and (work[i][0] >> col) & 1:
            work[i] = (work[i][0] ^ pm, work[i][1] ^ pa)
    r += 1

print("rank:", r)          # 135
print("free columns:", ...)  # [133, 136]

takeaway

When a multivariate public key system has only pure power terms with no mixed monomials, check whether the exponents are powers of the characteristic. If they are, the system is GF-linear on binary inputs regardless of apparent degree. Skip the Gröbner basis attacks and go straight to Gaussian elimination.

The security of HFE lives and dies by the size of the base field. Small base field equals small security.
