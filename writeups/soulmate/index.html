Soulmate

HTB Linux UDP + Web CrushFTP auth bypass → SSH → local pivot → root

Soulmate exposes a multi-surface compromise path: initial enumeration identifies a small set of services, but subdomain discovery reveals a file-transfer administration surface. A CrushFTP authentication bypass (CVE-2025-31161) enables administrative access without valid credentials, which is then leveraged to obtain a stable user foothold and pivot into a privileged internal service for root escalation.

Note: Public version omits flags, passwords, and unique identifiers. Commands use placeholders and focus on technique.

Overview

high-level chain

Entry point

Subdomain leads to CrushFTP interface; auth bypass enables admin takeover. :contentReference[oaicite:1]{index=1}

Escalation

Internal service access (localhost-only) enables privilege boundary bypass and root-level action.

Reconnaissance

port scan → vhost/subdomain discovery

Start with full TCP discovery and service fingerprinting. Even when the web surface appears limited, DNS/virtual-host discovery often reveals administrative or auxiliary interfaces.

nmap -sC -sV TARGET_IP nmap -p- --min-rate 10000 TARGET_IP

Perform host discovery for additional names, then validate by requesting with Host headers or adding entries to your local resolver (lab environment).

# examples (pick your tooling) ffuf -u http://TARGET_IP/ -H "Host: FUZZ.soulmate.htb" -w subdomains.txt # or DNS/vhost enumeration as applicable
Finding: Subdomain exposed a CrushFTP web interface, expanding the attack surface significantly.

Initial access

CrushFTP CVE-2025-31161 → administrative access

The CrushFTP instance was vulnerable to CVE-2025-31161, an authentication bypass that can result in administrative account takeover on affected versions. :contentReference[oaicite:2]{index=2}

# Verify product/version and exposure (example) # Access the CrushFTP interface over HTTP(S) and validate affected version range
Impact: Administrative access without valid credentials enables user management and configuration abuse.

Foothold

from admin surface → stable ssh access

With administrative control, create a controlled access path for a standard low-privileged user (lab-safe approach), then authenticate via SSH. The exact mechanism varies per box configuration; keep it reproducible and auditable.

ssh USER@soulmate.htb # foothold acquired (user context)

Privilege escalation

local pivot → internal service → privileged execution

Local enumeration revealed an internal-only service reachable via localhost on a non-standard SSH port. This is a common pattern: an administrative/management interface exposed only to the host itself, relying on “local trust” assumptions.

# identify listening services on localhost ss -lntp # connect to internal service (placeholder) ssh -p INTERNAL_PORT USER@127.0.0.1

The escalation path leveraged an Erlang component (BEAM ecosystem) that provided a command execution primitive when accessed through the internal channel. This resulted in root-level action.

Attack chain summary

  • Port discovery established baseline services; host discovery revealed an admin subdomain.
  • CrushFTP CVE-2025-31161 enabled authentication bypass / admin takeover on vulnerable versions. :contentReference[oaicite:3]{index=3}
  • Administrative capabilities were used to obtain a stable low-privileged foothold.
  • Local pivot accessed an internal-only service and abused an Erlang execution path for root escalation.

Security recommendations

defensive takeaways
  • Patch management: upgrade CrushFTP to fixed versions; monitor vendor advisories. :contentReference[oaicite:4]{index=4}
  • Reduce exposure: isolate admin interfaces (VPN / allowlist / mTLS), avoid public HTTP(S) access.
  • Credential hygiene: strong admin secrets, rotate after patching and suspected compromise.
  • Internal service hardening: do not rely on “localhost only” as a security boundary; enforce authz/authn.
  • Logging & detection: alert on anomalous admin sessions and configuration/user changes in FTP management suites.
