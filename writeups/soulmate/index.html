Soulmate

HTB Linux UDP + Web CrushFTP auth bypass → SSH → local pivot → root

Soulmate exposes a multi-surface compromise path: initial enumeration identifies a small set of services, but subdomain discovery reveals a file-transfer administration surface. A CrushFTP authentication bypass enables administrative access without valid credentials, which is then leveraged to obtain a stable user foothold and pivot into a privileged internal service for root escalation.

Overview

high-level chain

Entry point

Subdomain leads to CrushFTP interface; auth bypass enables administrative takeover.

Escalation

Internal service access (localhost-only) enables privilege boundary bypass and root-level action.

Note: Public version omits flags, passwords, and unique identifiers. Commands use placeholders and focus on technique.

Reconnaissance

port scan → vhost/subdomain discovery

Start with full TCP discovery and service fingerprinting. Even when the web surface appears limited, DNS/virtual-host discovery often reveals administrative or auxiliary interfaces.

nmap -sC -sV TARGET_IP nmap -p- --min-rate 10000 TARGET_IP

If the HTTP service is present, enumerate for virtual hosts / subdomains to locate non-obvious admin panels.

ffuf -w WORDLIST.txt -u http://TARGET_IP/ -H "Host: FUZZ.TARGET_DOMAIN" -fs 0 # or: gobuster vhost -u http://TARGET_IP -w WORDLIST.txt

Initial access

CrushFTP auth bypass → admin context

The admin interface was reachable and vulnerable to an authentication bypass. The goal is to obtain a privileged application context that can be translated into an OS-level foothold (file write, command execution, or credential recovery).

# validate target version + exposed endpoints (placeholder) curl -i http://CRUSHFTP_HOST:PORT/ # exploit step (placeholder) python3 exploit.py --target http://CRUSHFTP_HOST:PORT/ --mode bypass
Result: Administrative access established → pivot toward OS-level access.

Foothold

convert app control → stable shell / SSH

Use the gained control to establish a reproducible foothold (e.g., SSH keys, service creds, or a controlled outbound shell). Prefer persistence that does not rely on fragile web sessions.

# example: drop SSH key if file-write is possible (placeholder) mkdir -p ~/.ssh echo "SSH_PUBLIC_KEY" >> ~/.ssh/authorized_keys chmod 700 ~/.ssh chmod 600 ~/.ssh/authorized_keys

Privilege escalation

local pivot → internal service → root action

Local enumeration identified an internal-only service bound to localhost. By tunneling/pivoting locally, the attack gains access to functionality not exposed externally.

ss -lntup # if needed: forward internal port to attacker (placeholder) ssh -L 127.0.0.1:LOCAL_PORT:127.0.0.1:INTERNAL_PORT USER@TARGET_IP

Once the internal surface is reachable, look for trust assumptions (host-based allowlists, wrapper scripts, weak auth), and convert that into a root primitive.

# enumerate sudo and privileged helpers sudo -l ls -la /usr/local/bin # exploit privileged path (placeholder)
Impact: Root execution achieved → full compromise.

Attack chain summary

  • TCP baseline enumeration → identify candidate web surface.
  • Vhost/subdomain discovery → locate admin interface.
  • CrushFTP auth bypass → administrative control.
  • Translate app control into OS foothold (SSH/shell/creds).
  • Local pivot → internal-only service exposure → privilege boundary bypass.

Security recommendations

fixes mapped to each stage
  • Minimize admin exposure: isolate admin interfaces; restrict by network + strong auth.
  • Patch management: timely upgrades for internet-facing services (CrushFTP, gateways, panels).
  • Secrets hygiene: prevent credential reuse across services; rotate after incidents.
  • Internal service hardening: localhost-only is not a security boundary; enforce real auth.
  • Privilege policy: audit sudo/wrappers; remove trust-by-assertion patterns.
