Expressway

HTB Linux Medium UDP discovery → IKE leak → Cred reuse → Trust-based PrivEsc

This walkthrough documents a compromise path where the primary exposure was not visible in typical TCP scans. UDP discovery identified an IKE service, and an insecure configuration disclosed enough material to enable offline key recovery. Post-compromise, local information disclosure and hostname-based trust in a privileged wrapper enabled escalation to root.

Overview

high-level chain, kept reproducible

Entry point

Hidden UDP surface (IKE/500) with Aggressive Mode enabled, enabling offline attack against shared secrets.

Escalation

Trust-based privilege control accepted attacker-controlled hostname context, leading to root execution.

Note: This public version omits sensitive artifacts (keys, passwords, flags, unique hostnames). Commands use placeholders.

Reconnaissance

tcp-first scans → broaden to udp

Initial TCP scans indicated only SSH, which would normally reduce the attack surface to credential-based access. Expanding enumeration to UDP revealed additional services that are commonly missed if you rely solely on TCP.

nmap -sC -sV TARGET_IP nmap -p- --min-rate 10000 TARGET_IP
Finding: TCP footprint looked minimal, motivating UDP discovery for non-obvious exposure.
# UDP discovery (choose your preferred tooling) udpx -t TARGET_IP # or: nmap -sU --top-ports 200 TARGET_IP
Result: UDP/500 identified (IKE / IPsec key exchange).

IKE service analysis

aggressive mode → information leakage

IKE Aggressive Mode can leak negotiation material and identity hints. In practice, this can provide an offline verification oracle for pre-shared keys (PSKs) and reveal configuration metadata (IDs, proposals).

ike-scan -M -A TARGET_IP
  • IKE service reachable on UDP/500
  • Aggressive Mode enabled
  • PSK-based authentication
  • Negotiated proposals disclosed during handshake
Impact: Misconfiguration shifts the attack from online guessing to offline cracking.

Offline PSK recovery

extract material → dictionary attack

With Aggressive Mode material captured, the PSK can be tested offline against wordlists. The important aspect is not the specific key, but that the policy allowed weak shared secrets and an offline verification workflow.

# capture IKE material for offline testing ike-scan -A --pskcrack TARGET_IP > ike_material.txt # offline cracking (wordlist-driven) psk-crack -d WORDLIST.txt ike_material.txt
Risk: Shared secrets that are human-generated (memorable) often fall to wordlist attacks.

Initial access

credential reuse into ssh

Recovered authentication material was reused for SSH access. This is a common failure mode in environments where operational convenience outweighs separation of concerns between VPN/IKE and system logins.

ssh USER@TARGET_IP
Result: User-level access obtained; proceed to local enumeration and privilege boundary mapping.

Post-exploitation

local visibility → sensitive logs

Group membership granted access to proxy-related log files. Proxy logs frequently contain internal hostnames, service URLs, or admin activity trails — effectively functioning as an internal recon feed for an attacker.

id # enumerate readable logs and proxy artifacts ls -la /var/log cat /var/log/squid/access.log*
Finding: Internal naming and access patterns were exposed via logs, informing the escalation path.

Privilege escalation

non-standard sudo wrapper → trust on hostname context

A custom privileged wrapper enforced permissions based on hostname trust (i.e., “allowed if executed under a trusted host context”). This class of control is fragile if the asserted context is user-controlled, spoofable, or insufficiently validated.

# identify non-standard privilege helpers ls -la /usr/local/bin # example usage pattern (placeholder) /usr/local/bin/sudo -h TRUSTED_HOST /bin/bash
Impact: Improper trust validation enabled root execution, completing full compromise.

Attack chain summary

  • UDP service discovery uncovered a non-obvious IKE surface.
  • Aggressive Mode leaked enough handshake material for offline PSK testing.
  • Weak shared secret enabled credential recovery and SSH access.
  • Proxy logs disclosed internal context useful for escalation.
  • Hostname-trust in a privileged wrapper permitted root execution.

Security recommendations

fixes mapped to each stage
  • Disable Aggressive Mode: prefer Main Mode / IKEv2 with modern configurations.
  • Move away from PSKs: use certificate-based auth where possible; otherwise enforce long random secrets.
  • Reduce offline attackability: limit identity leakage and enforce strong policy/proposals.
  • Harden logging access: proxy logs should follow least privilege; avoid exposing internal names broadly.
  • Avoid trust-by-assertion: do not grant privilege based on caller-controlled “hostname” context; audit custom wrappers.
  • Operational controls: monitor VPN/IKE auth events; alert on abnormal handshake volume and repeated failures.

Tools

  • nmap (TCP/UDP discovery)
  • udpx (UDP enumeration)
  • ike-scan (IKE probing)
  • psk-crack (offline PSK testing)
